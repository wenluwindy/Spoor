# Spoor v0.5.0 规划（数据主权闭环 + 画布长成知识库）

> **状态：规划中。** 起点是 0.4.0 发布后的真实状态：欠账来自
> [RELEASE_v0.4.0.md](../release/RELEASE_v0.4.0.md) 明确记录的四条偏离，
> 地基来自 0.4.0 刻意铺下但尚未兑现的两块（节点级 `updatedAt`、数据目录迁移）。
> 边界延续既有决定：**不做 Linux 构建、不做移动端**、不做实时协作、不做手绘形状。

---

## 1. 起点盘点：0.4.0 之后还欠什么

### 产品侧最大的一个洞

卸载程序的提示原话是：「画布笔记存在浏览器数据库里，不在这个目录内。」

这就是洞。0.4.0 把数据主权做到了 90%：媒体文件在 `SpoorData/`、目录位置可自选、
备份快照齐全、导出格式开放——**但笔记本体仍在 webview 的 IndexedDB 里**，
用户看不见、摸不着、跟着 webview 的用户目录走。「把 SpoorData 放进网盘同步文件夹」
这条 0.4.0 铺好的路，目前同步的只是图片和文档，**不含笔记本身**。
一个把「本地优先」写进第一屏的产品，这是必须闭环的最后一块。

### 0.4.0 记录在案的欠账

| 项 | 出处 | 说明 |
|----|------|------|
| API Key 明文存 localStorage | 0.4.0 规划 T9 | 当时决定「与 0.5.0 的存储方案一起定，避免搬两次」——现在到期 |
| 序列化字段注册表 | 0.4.0 偏离 4 | 四套序列化各自维护字段映射；本版 A 线要加第五套（文件镜像），动机从「未来收益」变成「现在就疼」 |
| 键盘优先级栈 | 0.4.0 偏离 4 | Esc 三个处理者靠隐式顺序协调，注释在扛 |
| 演示模式 | 0.3.0 差距清单 P2 | 当时说「等小地图与模板站稳」——0.4.0 站稳了 |
| 模板管理 | 0.4.0 C10 收尾时的简化 | 只有右键子菜单删除，没有重命名/预览 |
| `AgentConfig.color` 字段无 UI | 0.4.0 前探查发现 | 接入或删除，别让字段悬着 |

### 0.4.0 新攒下的可能性（地基已就位，一步之遥）

- 节点/连线有了 `createdAt/updatedAt` → 基于时间戳的合并**可以做了**
- 标签落库且有 multiEntry 索引 → 差一个**按标签筛选的视图**（现在只能搜）
- 区域框 + 批量移动 + 对齐 + 可撤销写入全齐 → **AI 整理画布**（聚类分组）的全部零件都在货架上
- `createAiCardAndStream` 工厂 + Agent 人格体系 → **多人格接力/圆桌**只是编排问题
- 搜索的流式扫描底子 → 跨画布/长文/研究的**全局搜索**入口
- `focusNode` + 小地图 + 连线拓扑 → **演示模式**就是一个播放器

## 2. 主题

0.3.0「让人敢把东西放进来」→ 0.4.0「把已有的做对，把 AI 做深」→

**0.5.0：「笔记回到你的文件夹，画布长成知识库」。**

## 3. 建议范围

### 主线 A：笔记落文件（P0，本版核心）

1. **文件镜像层**：IndexedDB 保持为**运行时主库**（保留 Dexie + `useLiveQuery` 的全部
   响应式生态），新增一层持续镜像——每次写库后防抖（~2s）把**变更画布**序列化到
   `SpoorData/notes/<canvasId>.json`（含节点、连线、AI 历史；长文与人设各一份文件）。
   写入走 Rust 侧原子写（临时文件 + rename），文件带 `revision` 计数与校验和。
   - **刻意不换 SQLite**：把 Dexie 换掉是数月级重写且丢掉 live query 生态；
     镜像层改动小一个数量级，且文件格式对用户透明（JSON 可读、可 diff、可进 git）。
   - 镜像格式复用 JSON Canvas 的结构（`spoor` 扩展字段承载全量语义）——
     **用户文件夹里躺着的就是 Obsidian 打得开的 `.canvas` 的超集**，不是私有 dump。
2. **启动对账**：启动时逐画布比较文件与库的 `revision`/`updatedAt`：
   - 文件更新（典型场景：另一台电脑经网盘同步改过）→ 提示后按节点级
     `updatedAt` LWW 合并进库；
   - 库更新 → 正常，补写镜像；
   - 检测网盘冲突副本（`xxx (conflicted copy).json` 等命名模式）→ 提示用户择一。
   - **明确边界**：支持的是「非同时在线的多设备」，两台机器同时编辑同一画布
     不在本版范围（那是 CRDT 的领域，写进文档）。
3. **API Key 出 localStorage**：迁到 Tauri `app_config_dir` 下的配置文件，Windows 上用
   DPAPI（`windows` crate 的 `CryptProtectData`）加密、macOS 进 Keychain；
   迁移一次性完成，失败回退旧位置并提示。备份继续排除密钥。
4. **收编既有备份**：每日快照与「导出全部数据」改为基于镜像文件打包（镜像本身就是
   持续热备份，快照退化为按日归档镜像目录），删掉一套独立的序列化路径。

### 主线 B：画布长成知识库（P1）

5. **全局搜索（`Ctrl+Shift+F`）**：一个面板搜全部——画布节点（复用流式扫描）、
   长文、研究会话；结果按来源分组，回车直达（切画布并定位 / 打开长文 / 打开报告）。
6. **标签视图**：画布顶部（或搜索面板内）标签栏，点亮一个标签 → 命中卡片保持原样、
   其余淡出为幽灵态；多标签为并集。标签重命名/合并入口放这里。
   multiEntry 索引已就位，这是纯 UI 工作。
7. **演示模式**：右键区域框或多选 →「从这里开始讲」；按连线拓扑序（可拖动调整）
   逐卡聚焦放映，方向键翻页、Esc 退出。只做逐卡聚焦 + 顺序编辑，
   **不做**样式主题、激光笔、导出幻灯片——那是 pptx 的战场。

### 主线 C：AI 做深第二程（P1）

8. **AI 整理画布**：多选（或全选）→「帮我分组」：AI 按主题聚类，给出
   「N 个区域框 + 卡片归属 + 框标题」的**预览**（虚影渲染），确认后一步落库、
   一次撤销可回滚。这是散乱画布到结构化知识的关键一跳，所有零件
   （frame、批量移动、对齐、可撤销批量写）都是 0.4.0 的现货。
9. **人格接力**：AI 卡右键 →「让另一个人格接着说」：选一个 Agent，
   以当前卡为上下文出一张新卡并连线（真知镜挑刺 → 熨烫师改写的天然工作流）。
   基于 `createAiCardAndStream` 工厂，编排成本极低。
10. **Research Lab 中途落卡**：分步执行过程中，每一步的产出卡片上给「落到画布」——
    不必等整份报告完成才能把有价值的中间结论接进思考网络。

### 主线 D：工程底账（贯穿）

11. **序列化字段注册表**：在 A 线镜像格式动工**之前**做——一张
    `CanvasNode 字段 → {jsonCanvas, clipboard, mirror, backup, markdown} 处理器` 的表，
    五个序列化器读同一张表，新增字段漏一处直接编译报错。
12. **键盘优先级栈**：显式的 `modal > linkdrag > menu > canvas` 分层，替掉 Esc 的隐式约定。
13. **Playwright 冒烟线**：`npm run dev` 起 vite，跑一条最小交互链
    （建卡 → 连线 → 拖动吸附 → 撤销 → 搜索定位）。0.4.0 的大量交互改动全靠
    单测 + 人肉验证，回归网需要这最后一层。
14. **小件**：模板重命名与预览；`AgentConfig.color` 接入人格卡片显示（或删字段）；
    App.tsx 继续拆（目标 < 900 行）。

> **不进 0.5.0**：Linux 构建与移动端（用户决定）、实时协作与 CRDT（对账边界写明后，
> 留给真实需求投票）、手绘形状、卡片级双链（Spoor 的链接语义是画布上的线与跨画布
> 传送门，文本内 `[[]]` 双链与空间心智相竞争，先不引入第二套）。

## 4. 推荐取舍

如果只能做一半：**A 全部 + D11（注册表，A 的前置）+ C8（AI 整理画布）**。

理由：A 线是产品立场的最后兑现——「本地优先」四个字在笔记还锁在浏览器数据库里时
是打折的，而它同时顺手解决了多设备这个用户最常问的问题的 80% 场景（网盘文件夹）。
C8 是本版对「AI 站在画布里」叙事的最大增量：从「AI 生产卡片」到「AI 整理你的卡片」。
B 线三件都是好功能但都可以独立后补；D12/13/14 随开发节奏见缝插针。

## 5. 风险

| 风险 | 说明 | 对策 |
|------|------|------|
| 镜像与库脑裂 | 两个真相源，对账逻辑错一处就是丢数据 | 文件带 revision + 校验和；对账「合并进库」前自动快照；合并逻辑纯函数化，用双向老化数据的用例矩阵测试 |
| 网盘同步的半截文件 | 网盘可能在写入中途同步走临时状态 | Rust 侧原子写（temp + rename）；读侧校验和不符则忽略该文件并告警，不用坏数据覆盖库 |
| 镜像写入的性能回退 | 0.4.0 刚把高频写库消灭，镜像别把它请回来 | 防抖 2s + 只序列化脏画布 + 写入在 Rust 线程，渲染进程只发变更信号 |
| 密钥迁移失败锁死用户 | 迁移路径上任何一步崩了都不能让用户丢配置 | 先复制后切换，旧值保留一个版本周期；DPAPI/Keychain 失败降级为明文文件 + 设置页提示 |
| AI 整理画布乱动用户的卡 | 破坏性远大于生成新卡 | 预览-确认两段式；落库整批一步撤销；框内已有的卡不移动（只框不挪是保守默认） |
| 演示模式范围膨胀 | 「再加个主题」「再加个导出」没有尽头 | 范围钉死在「聚焦播放器」，超出的一律记 0.6 |
| 对账提示打扰单机用户 | 从不跨设备的用户不该看见合并对话框 | 文件与库指纹一致时静默；只有真检测到外部变更才开口 |
